# Template Method(樣板方法)

把演算法的固定流程寫死一次,把其中會變的步驟留成「洞」,交給呼叫端填入不同實作。

傳統物件導向語言(如 Java、C#)會用抽象類別定義流程,子類別繼承後覆寫可變步驟。**Go 沒有繼承**,慣用做法是改用「函式欄位」(function field)取代抽象方法覆寫:把可變步驟宣告成 struct 裡的函式欄位,由呼叫端組出一組函式值,固定流程則交由一個獨立函式依序呼叫這些欄位。

## 角色

| 角色 | 對應本專案 | 職責 |
|------|-----------|------|
| **Template Method**(固定流程) | `Run` | 定義演算法骨架,固定依序呼叫 Read → Process → Write,回傳最終結果;流程順序本身不可被呼叫端改變 |
| **可變步驟**(hook) | `Steps.Read`、`Steps.Process`、`Steps.Write` | 三個函式欄位,分別對應「取得資料」「處理資料」「輸出結果」;呼叫端透過填入不同函式值來客製化每個步驟的細節 |

## 執行

```sh
go test ./...
```

`example_test.go` 中的 `ExampleRun` 示範:`Read` 回傳 `[1 2 3 4]`,`Process` 過濾出偶數得到 `[2 4]`,`Write` 用 `fmt.Sprint` 轉成字串輸出。`go test` 會實跑並比對 `// Output:` 的內容。
